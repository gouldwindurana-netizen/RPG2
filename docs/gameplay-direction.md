# A consistent world-exploration RPG

The game is an original four-person party RPG. New features should support one coherent play loop:

**Town → overworld travel → encounters and discoveries → dungeon → story outcome → new route → town.**

The overworld is a place to walk and explore, not a list of level-selection buttons. Town entrances, bridges, passes, and ferry routes make geography useful. Story progress can open a route, while optional paths offer treasure and harder enemies. The map menu provides orientation without teleporting the party.

Towns protect ordinary movement from encounters and provide conversations, equipment, supplies, and recovery. Wilderness and dungeons use their own enemy tables and fixed regional strength. Revisiting an earlier road should show how the party has grown. New colors and names identify stronger variants; gaining a level does not silently recolor old enemies.

Battles collect the party's commands, then resolve them sequentially. Magic has separate tiered charge pools. Items are shared, equipment remains understandable, and elemental choices matter. Keyboard commands, clear targeting, repeat commands, and adjustable playback speed support this structure.

The interface uses blue windows, silver borders, compact white text, and a visible selection cursor. Menus describe actual game actions. Story dialogue leaves the world visible, and background exploration stops while a dialogue or menu is open. Town, world, and dungeon transitions should be easy to understand.

The hero creator offers a name, job, appearance choices, and he/him or she/her story wording. Older saved character profiles remain readable so an interface simplification does not discard progress.

The public game and its documentation use original content and branding. This direction governs future additions as well as the current campaign expansion.
